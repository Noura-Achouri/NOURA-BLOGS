Shodan: The Search Engine for Every Connected Device

Google indexes web pages. Shodan indexes devices — webcams, routers, servers, databases, traffic lights. Here's how it works, what you can search for, and (most importantly) how to use it to protect your own stuff.

What is Shodan?

Shodan is a search engine, but instead of crawling websites it crawls the internet itself. It continuously scans public IP addresses, connects to open ports, and records what answers back — a web server, an SSH login prompt, a camera stream, a database asking for a password.

Think of it like this: Google shows you the content of the web. Shodan shows you the machines behind it. Its tagline is literally "the search engine for the Internet of Things".

Google vs Shodan

Why this matters to me

As a student, Shodan is the fastest way I've found to answer the question "what does the internet actually look like from the outside?" — it turns abstract networking concepts into something I can search and see.

How does it work?

The three steps it repeats

Under the hood, Shodan does three simple things over and over:

  1. Probe — it sends a request to a huge range of IP addresses on common ports (80, 443, 22, 21, 23, 3389, 8080…).
  2. Listen — whatever the device replies with is called a banner: a small greeting that usually reveals the software name and version.
  3. Index — that banner is stored and made searchable, together with the IP, country, ISP and open ports.

What a banner looks like

A banner you might see from an SSH server looks like this:

$ nc 203.0.113.10 22
SSH-2.0-OpenSSH_7.4

That single line tells you the host is running OpenSSH 7.4 — and a quick search tells you which known vulnerabilities affect that version. That's the whole idea: exposure is discoverable.

Search filters worth knowing

Shodan searches are just keywords plus filters. These are the ones I use most:

Filter cheat-sheet

Combining filters

You can combine them into very targeted queries:

# Find nginx web servers in Tunisia
product:nginx country:TN

# Find MongoDB instances with no password prompt
product:MongoDB port:27017

# Find exposed webcams
"webcamXP" has_screenshot:true

Reading a result

Anatomy of a result card

A typical Shodan result card gives you:

  • IP address + hostname — where the device lives.
  • Open ports — which doors are unlocked.
  • Banner / HTTP headers — what software is answering.
  • Location & ISP — country, city, organisation.
  • Vulnerabilities (CVEs) — known issues linked to that version.
  • Last seen — how fresh the data is.

Freshness check

💡
The most useful field is often Last seen. A result from two years ago may no longer exist — always verify before drawing conclusions about a host.

Using Shodan to defend

This is the part I care about most as a student: Shodan is a fantastic mirror. It shows your systems exactly how a stranger sees them.

My 5-step self-check

  1. Look yourself up. Search your own public IP (net:your.ip.here/32) and check what ports are visible.
  2. Close what shouldn't be open. Use a firewall — on Linux, ufw makes this painless: 
    sudo ufw default deny incoming
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status verbose
  3. Fix default credentials. Cameras, routers and databases are usually exposed because nobody changed admin/admin.
  4. Update the software. Old versions of OpenSSH, nginx or MongoDB appear on Shodan precisely because they carry known CVEs.
  5. Monitor continuously. Shodan can alert you when a new device or open port appears in your organisation's IP range — that's an early warning system.

Mistakes to avoid

⚠️
Common beginner mistake: thinking "nobody will find my device, it's only on port 8080". Automated scanners don't get tired — an exposed service on the public internet is usually discovered within minutes.

Ethics & legality

Searching Shodan is legal — it only shows publicly reachable information. What you do next is what matters:

Green light / red light

  • ✅ Searching and learning — fine, and encouraged.
  • ✅ Checking your own or your company's exposure — fine, with permission.
  • ❌ Connecting to, logging into, or testing a system you don't own — not fine.
  • ❌ Using it to build target lists for attacks — illegal.

A good rule: if you wouldn't do it to a stranger's front door in real life, don't do it to their server.

Mini glossary

Terms I keep mixing up

Port
A numbered "door" on a machine where a service listens (22 = SSH, 80 = HTTP, 443 = HTTPS).
Banner
The greeting a service sends when you connect — often reveals software and version.
CVE
A public ID for a known security vulnerability in specific software.
Attack surface
Everything reachable from the outside: open ports, services, APIs, exposed credentials.
📌
Takeaway: Shodan isn't a hacking tool — it's a mirror. The moment you put something on the internet, someone can see it. Look yourself up first, then lock the doors.
